# 秦陵归藏棋局

秦陵归藏棋局是一个浏览器棋类规则原型，同时支持平面双层六边形棋盘和立体双锥六面体棋盘。项目用于验证棋子移动、上浮下沉、成对传送阵、自定义布局和限时 AI 搜索能否共用同一套规则模型。

> 当前仍是规则讨论与交互验证阶段。本文描述项目现有实现，不表示全部规则已经最终定稿。

## 功能概览

- 平面双层棋盘与立体六面体棋盘。
- 王、后、象、兵四类棋子及吃子、降级、升级规则。
- 后每回合三次单步移动、逐步提示和逐步回退。
- 两组成对、双向传送阵及传送观察态。
- 王加持：每方王每局三次机会，回合开始时可一次加持身边一格内的多枚己方象或兵，每枚消耗一次机会。
- 平面整层升沉，以及立体顶点、公共棱、三角面的局部升沉。
- 平面布局编辑、立体装配、同名布局同步和本地持久化。
- Web Worker 中运行的 3 秒限时 AI 搜索。
- 人工走棋、单步算法演示、连续模拟、暂停和重新开局。

## 环境要求

- Node.js。
- 支持 Web Worker、CSS 3D 和 `localStorage` 的现代浏览器。

项目没有外部运行时依赖，通常不需要执行 `npm install`。

## 快速开始

在本目录中启动服务：

```powershell
cd flat_hex_game_prototype
npm start
```

浏览器访问：<http://127.0.0.1:8780>

本地 Node 服务同时提供静态页面和布局存储接口。若静态部署或项目目录不可写，布局会自动保存到当前浏览器的 `localStorage`。

## 基本操作

- 选择己方棋子后，点击高亮位置完成移动。
- 点击“王加持”可在回合开始前选择身边一格内的多枚己方象或兵升级，加持后本回合仍正常走棋。
- 后需要连续完成三次单步移动，界面会显示已走步数和剩余步数。
- “算法一步”计算并执行当前行动方的一手；连续模拟可随时暂停或继续。
- “预览背面”只切换平面棋盘显示内容，不修改当前层、回合、历史或棋子状态；预览期间不能移动棋子或运行算法。
- “回退一步”在普通回合中恢复上一完整手；后尚未走完三步时，只撤销最近一次单步。
- 暂停、重新开局或进入编辑会终止当前后台搜索，避免过期结果继续落子。

## 棋子规则

### 移动与吃子

| 棋子 | 当前实现 |
| --- | --- |
| 王 | 只在棋盘顶点之间沿真实棱移动，不能进入六边形中心。路径中的棋子不会阻挡王，目标点占用仍参与合法性和吃子判断。 |
| 后 | 每回合必须完成三次单步，普通移动每步可以改变方向，也可以消耗一步原路返回已经走过的位置；只有第 3 步可以吃子。 |
| 象 | 按现有菱形对角线路径移动；立体棋盘中可跨相邻面延续路径。 |
| 兵 | 按现有一步移动和同类吃子规则行动。 |

相邻面共享的公共棱点和公共顶点只算一个物理位置，最多放置一枚棋子。板面坐标只是该位置在渲染、交互和存档时使用的锚点，不决定规则归属。

### 吃子结算

| 攻击关系 | 结算结果 |
| --- | --- |
| 后吃象 | 后与象交换位置，象降级为兵；攻击方后获得 3 回合传送能力。 |
| 象吃兵 | 被吃的兵移除，象占据目标位置；可选择保持为象或升级为后，升级后获得 3 回合传送能力。 |
| 兵吃兵 | 被吃的兵移除，攻击方兵占据目标位置；可选择保持为兵或升级为象。 |
| 王攻击相邻的敌方后 | 双方保持原位，敌方后降级为象。 |
| 其他允许的普通吃子 | 按目标占用和当前棋种规则结算。 |

降级属于成功吃子。任何具有传送能力的棋子被降级时，会立即失去传送能力。

### 王的特殊限制

- 平面王只在六边形的六个顶点之间移动，不能走到中心或非顶点交点。
- 立体王沿立体图形的真实棱在顶点之间移动。
- 王的移动不受路径中间棋子阻挡，但不能忽略目标顶点的占用。
- 王可以攻击表面相邻一格内的敌方后，包括立体棋盘跨相邻面的情况；结算后王不移动，后原地降级为象。

### 王的加持

- 每方王在每个棋盘形态的整局对弈中有 3 次加持机会，重新开局恢复为 3。
- 行动方可以在本回合开始、移动之前决定是否加持；一次动作可同时加持王身边恰好一格的多枚己方棋子，每加持一枚消耗一次机会。
- 平面棋盘按六方向相邻格点判定；立体棋盘按表面相邻点判定，可以跨公共棱和相邻面。
- 只有己方象和兵可以接受加持：兵升为象、象升为后；后已是最高级，不能获得加持。
- 同一回合同一枚棋子只能被加持一次；被加持的棋子本回合仍可正常移动，吃兵后仍按原有“升级或保持原级”模式结算。
- 象经加持升为后时不获得 3 回合传送能力；之后的普通后规则照常结算。

## 后的三步回合与回退

人工操作时，后的一整个回合被拆成三次连续单步：

1. 选择后并走第 1 步。
2. 系统保持该后为当前操作棋子，并提示剩余 2 步。
3. 走完第 2 步后继续提示最后 1 步。
4. 第 3 步完成后，才正式提交这一完整回合；只有这一步允许吃子。

后可以在三步内重复经过此前的位置，例如 `1 → 2 → 1` 或 `1 → 2 → 3 → 2`；每段移动都消耗一步，不会因为原路返回而返还步数。

未提交前可以逐步回退：

- 普通单步回退到该步之前的位置，并恢复一步额度。
- 正在选择是否传送时，可以从选择界面直接回退。
- 已进入传送观察态时，回退会同步恢复传送前的层级显示和剩余步数。
- 第 3 步正式提交后，再执行回退会恢复整个回合开始前的状态。

重新开局或保存新布局并开局会清空回退历史。编辑、背面预览、动画和 AI 搜索期间不能回退。

## 传送阵

### 默认配对

默认布局包含两组成对、双向传送阵：

- `1A-5 ↔ 4B-5`
- `3A-5 ↔ 6B-5`

同一对端点使用相同颜色，并显示为略大于棋子的虚线圆圈。潜藏层端点会降低透明度；平面使用“背”标记，立体使用“内”标记并显示板面点号。

### 传送能力

- 后吃象后获得 3 回合传送能力。
- 象吃兵并升级为后时获得 3 回合传送能力。
- 能力按 `3 → 2 → 1 → 消失` 显示，每完成一个正式回合消耗一次。
- 再次获得能力时刷新为 3。
- 有能力的棋子一旦降级，能力立即清除。

当前只有升级后的后可以实际使用传送阵；尚未升级的象和兵不能传送。

### 传送操作与结算

- 后站在传送点上时，可点击自身位置并消耗一步传送到配对端点。
- 后用普通一步抵达传送点时，系统询问“传送”或“正常移动”。
- 传送本身占用一次单步，传送后仍可使用剩余步数。
- 平面棋盘会暂时显示出口层；立体棋盘进入传送观察态，暂时呈现全部六个内部面。
- 观察态使用眼睛标记，并让立体棋体的可见物理棱与当前后产生脉冲血红光，用于提示这只是临时层级展示。
- 若后在第 3 步完成吃子，观察态结束后再根据吃子位置执行正式升沉。
- 若传送后没有吃子，5 秒后或手动结束观察即可提交动作：后保留在出口位置，但不触发永久升沉。

空门传送是合法动作，也会进入 AI 搜索。传送后未吃子不会把棋子退回入口，其影响仅是不触发永久升沉。

## 平面双层棋盘

### 默认板块映射

布局三的初始上层六区依次为：

```text
5A / 6A / 3A / 4B / 1A / 2A
```

对应下层按实体板垂直镜像关系保存：

```text
3B / 6B / 5B / 2B / 1B / 4A
```

两层分别保存棋盘结构和棋局状态。“预览背面”只读取另一层，不改变正式状态。

默认棋子位置按两张实体棋盘照片标定：照片一对应初始上层，照片二对应下层预览和首次升沉后的布局。照片中的手写黑点表示落子点，红色三角轮廓只用于辅助标示象，不是额外棋子。

### 平面升沉

平面棋盘发生成功吃子后：

1. 先完成当前层吃子、降级、换位或升级结算。
2. 当前棋盘及其全部棋子整体下沉。
3. 正下方对应的另一套棋盘及其棋子整体上浮，成为新的可操作层。

升沉不会旋转六个空间槽位。例如同一槽位的 `4A` 下沉时，由其正下方的 `4B` 原位上浮，而不是切换为镜像预览顺序。同一物理交点上下都有棋子时，两枚棋子随各自棋盘交换层级。

## 立体棋盘

### 空间移动

- 棋子沿六面体连续表面移动，到达公共棱后可进入任一相邻面。
- 后的三步路线和象的菱形对角线可以跨面延续。
- 公共棱点和公共顶点使用统一物理位置判定，不能因相邻面的坐标别名而重复放置棋子。
- 公共位置上的棋子在所有三角面之后绘制，避免旋转视角时被相邻面局部遮挡。

### 立体局部升沉

立体棋盘发生吃子时，不旋转或交换整个立体棋体。升沉范围只由被吃棋子的物理位置决定，与攻击者棋种、起点和移动路线无关。

| 被吃棋子位置 | 升沉范围 |
| --- | --- |
| 公共顶点 | 只交换该物理顶点上的外层与内层棋子；所有棱和三角面保持不变。 |
| 公共棱中间交点 | 只交换该物理棱及其两个端点上的外层与内层棋子；三角面保持不变。 |
| 三角面内部 | 交换该三角面及其三条边界上的外层与内层棋子，并切换该面朝向；其他面保持不变。 |

没有吃子的普通移动和空门传送都不触发永久升沉。传送观察态只临时显示内部面；如果随后发生吃子，仍按上表根据被吃棋子的位置结算。

## 布局编辑与存储

### 新建平面布局

“新建布局”会创建一个空白双面棋盘：

- 清空 A、B 两面的棋子。
- 恢复默认板块排列和方向。
- 自动加入两对默认传送阵。
- 只有主动保存后才写入布局库。

编辑器支持放置或替换双方的王、后、象、兵，也可清空交点。每个交点最多一枚棋子；双面合计必须恰好有一枚白王和一枚黑王，且王只能放在六边形顶点。

传送阵只能在平面编辑器中修改。选择“传送阵”工具后，依次选择两个端点创建一对；点击已有端点会删除整对。布局只保存完整配对。

### 板块拆装

平面编辑器还支持对六块实体三角板执行：

- 旋转：连同板上棋子顺时针旋转 120°，三次恢复原方向。
- 翻转：沿垂直轴镜像并切换该实体板的 A/B 面。
- 交换：选择两块板后交换其空间位置。

这些操作会同步维护整板另一面的垂直镜像槽位。旧版水平轴布局在读取时会自动迁移，并尽量保持棋子身份及其板内位置。

### 立体装配

- 保存平面布局后，立体列表自动生成同名“待组装”入口。
- 立体编辑器只读显示同名平面布局的棋子和传送阵；传送端点会随安装、旋转和翻面更新，但不能在立体编辑器中修改。
- 六块板必须全部安装且不存在物理位置冲突，才能保存立体布局或开局。
- 平面棋子变化会实时影响同名立体布局；立体装配不会反向改写平面结构。
- 相同名称可同时保存一条平面记录和每种棋盘结构（双锥六面体、四面体插板）各一条立体记录，覆盖其中一种不会覆盖另一种。
- 立体列表中每种结构是独立条目，载入、启用和删除都只作用于所选结构；编辑器内切换结构时，两种结构各自保留独立的装配进度。
- 启用立体布局会记录其棋盘结构，重新开局按该结构呈现棋盘。

布局库包含默认平面布局，以及三组平面、立体同名且可直接游玩的测试预设。旧记录缺少棋盘形态时按平面布局读取；缺少棋子板面归属字段时，会根据现有平面位置补齐。

### 持久化

本地服务可写时，布局保存在：

```text
layout-data/layouts.json
```

服务不可用、静态部署或目录不可写时，自动退回浏览器 `localStorage`。

“启用”只更新该棋盘形态以后重新开局所使用的起点，不重置当前棋局或退出编辑；“保存并开局”会保存当前结构并立即开始新局。装配不完整、同名平面来源失效、棋子冲突或缺少王时，不会覆盖已有可用存档。

## AI 搜索

平面和立体棋盘共用 `game.js` 中的规则与搜索入口，不维护两套互相分叉的 AI 逻辑。

当前搜索策略包括：

- Dedicated Web Worker 后台搜索，避免阻塞棋盘动画和交互。
- 单步名义时间预算 3 秒，采用迭代加深。
- Alpha-Beta 剪枝、主变例排序和置换表。
- 吃子、升级和关键跨层动作的静态延伸。
- 同时评价当前层与潜藏层，并考虑机动性和传送能力。
- 王加持与普通移动在同一手内组合搜索，并计入升级收益与机会消耗。
- 用局面指纹辅助处理近期重复走法。
- 超时后丢弃未完成深度，返回最后一个完整搜索深度的动作。

这里的“最优”是当前评估函数和时间预算下最后完整深度的 Minimax 结果，不代表已经求得全局理论最优解。

```powershell

```

| --- | --- |
| `index.html`、`styles.css` | 页面结构、平面棋盘与通用界面样式。 |

| `ai-benchmark.mjs` | AI 基准命令入口。 |

## 当前限制

- 项目仍是单机浏览器原型，不包含联网对战、服务端 AI 或账户系统。
- AI 在有限时间内近似选择最优动作，不保证理论最优。
- 立体传送阵只能查看，必须回到同名平面布局中成对编辑。
- 立体棋盘依赖 CSS 3D 和浏览器渲染，不同设备上的动画流畅度可能不同。
- 规则仍可能随讨论调整；修改规则时应同步更新测试、页面说明和本文档。
