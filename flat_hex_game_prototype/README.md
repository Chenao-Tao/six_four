# 平面六边形棋盘原型

本原型要验证的问题是：六个同规格三角形拼成的半径 4 六边形网格，能否用统一图结构表达王、皇后、象、兵的路线，并让玩家与自动演示共用同一套合法移动算法。

当前规则假设会显示在页面右侧。它们是用于讨论的原型定义，不代表最终规则已经锁定。

后吃象时双方换位且象降兵；象吃兵时兵消灭且象占据目标位置；兵吃兵或王后占据目标位置；王吃后时双方留在原位且后降象。降级属于成功吃子，符合条件的攻击方可以选择是否升级。

皇后每回合仍必须完整移动三步，但人工操作改为连续选择三次单步，界面持续提示已走步数和剩余步数；只有第3步可以吃子。自动演示仍把三步视为一个完整动作，在专用 Web Worker 中进行3秒限时迭代加深，执行最后一个完整搜索深度的动作，并逐层展示当前候选。搜索使用 Alpha-Beta 剪枝、置换表和吃子静态延伸，同时评价当前层与潜藏层，把升级与保持原级纳入评估，并通过局面指纹优先避开近期重复走法。连续模拟运行时可以随时暂停或继续；暂停、重开或编辑会立即终止后台搜索。在立体棋盘中，视角会平滑跟随当前计算的棋子和最终落点，手动拖动仍可接管视角。

传送阵默认位于实体板面编号的 5 号点，随三角板交换、翻面和旋转移动：`1A-5 ↔ 4B-5`、`3A-5 ↔ 6B-5`。门以略大于棋子的虚线圆圈显示，同一对端点颜色相同，潜藏层端点降低透明度；平面标记使用“背”、立体标记使用“内”并显示具体板面点号。平面自定义编辑可进入“传送阵”工具，依次选择两个端点创建一对，点击已有端点删除整对；布局只保存完整配对，立体结构实时读取同名平面布局的传送阵。后吃象成功，或象吃兵并选择升级为后时，获得 3 回合传送能力；能力显示在后身上并按 `3 → 2 → 1 → 消失` 递减，该后每完成一个正式回合消耗一回合能力，重新获得能力时刷新为 3。任何带传送能力的棋子一旦被降级，能力立即清除。能力有效且后站在门上时，可点击自身位置用一步穿越；后用普通一步走到门上时，系统询问下一步传送还是继续当前面。穿越后平面棋盘临时切到出口层，立体棋盘则临时呈现全部六个内部面，并用眼睛标记进入检测状态；剩余步数继续逐步选择。第3步在出口层吃到可吃的象时，先结束内部观察，再按被吃子所在的顶点、公共棱或三角面正式执行局部上浮下沉；没有吃子时，5秒后或手动结束检测也会提交完整动作，后保留在出口位置，但只关闭临时观察，不产生永久升沉。尚未升级的象和兵不能使用传送阵，空门传送同样是合法完整动作并纳入 AI 搜索。

棋盘采用布局三的双面拼图。初始朝上面的六区依次使用 `5A / 6A / 3A / 4B / 1A / 2A`，下层统一按实体板垂直镜像关系保存，对应为 `3B / 6B / 5B / 2B / 1B / 4A`。两层各自保存棋盘配置和棋局状态；成功吃子会先结算当前层，然后不旋转棋盘，让当前棋盘与其全部棋子整体下沉，并让正下方对应的另一套棋盘与棋子整体上浮。换层过程保持六个空间槽位不动，例如同一槽位上的 `4A` 下沉时由其正下方的 `4B` 原位上浮，不会切换到镜像后的背面观看顺序。同一物理交点上下都有棋子时，两枚棋子随各自棋盘直接交换层级。

初始棋子位置按两张实体棋盘实拍图重新标定到六边形网格交点。照片一作为初始上层，照片二作为下层预览与首次换层后的初始布局；手写黑点是落子点，红色三角轮廓只用于辅助标出“象”，不作为额外棋子。

“预览背面”只切换显示内容，不修改当前层、回合、历史或棋子状态；预览期间棋子和算法控制均不可操作。吃子触发换层后，棋盘不旋转，原下层棋盘及其棋子整体上浮成为新的可操作层。

平面和立体棋盘都提供“回退一步”。每次人工或算法成功落子后会保存完整的走前状态，可连续逐手恢复棋子、行动方、手数、双层位置、传送能力、胜负和局面历史；重新开局或保存新布局并开局会清空回退记录。编辑、背面预览、动画和算法搜索期间暂不可回退。

“自定义棋盘”会进入独立的空白双面编辑状态。平面布局存档区的“新建布局”会清空 A、B 两面的棋子，恢复默认板块排列与方向，并自动加入 `1A-5 ↔ 4B-5`、`3A-5 ↔ 6B-5` 两对默认传送阵；新草稿只有在主动保存后才会写入布局库。点击任意交点可以设置或替换白/黑方的王、后、象、兵，也可以清空该点；A、B 两面分别编辑。每个交点最多一枚棋子，双面合计必须有且仅有一枚白王和一枚黑王，且王只能放在中心或六个外角。取消编辑不会改变原棋局，保存后从 A 面朝上、白方第 1 手开始。

自定义编辑包含“棋子摆放”和“板块拆装”两种工具。板块拆装模式下可直接选择六块三角板中的任意一块：旋转会让该板及板上的棋子顺时针转动120°，连续三次回到原方向；翻转会沿垂直轴镜像并交换该实体板的 A/B 面；交换会让它与随后点击的另一块板互换位置。三种操作都会同步维护整板另一面的垂直镜像槽位，方向随实体板一起交换。立体装配编辑会只读显示同名平面布局的传送阵，端点随板块安装、旋转和翻面更新，但传送阵仍只能在平面编辑中成对修改。旧版按水平轴保存的布局会在读取时自动迁移，棋子身份及其在三角板内部的位置保持不变。

每个方案使用同一个名称保存平面与双锥六面体两种结构，两个存档区只在对应编辑形态下显示。保存平面方案后，立体列表会自动生成同名的“待组装”入口，但不会把未完成的立体结构写入存档；完成六块板装配后，真实立体记录会替代该入口。平面记录保存双面三角板结构和棋子在实体板上的位置；同名立体记录只保存六块板的装配槽位、朝上面和旋转角度，不重复保存棋子。载入、切换或开局时，立体结构会实时读取同名平面记录的棋子并映射到对应实体板，因此修改平面棋子会同步影响立体棋盘，而立体旋转、翻面或重装不会改写平面结构。选择立体棋盘后会在当前页面的棋盘区域显示装配工作台，右侧只显示立体存档控件：六块实体三角板排列在待选区，中间显示六面体空骨架，并提供六个始终可点击的骨架槽位。选中待选板或骨架上的已安装板时，会预览该板当前朝上的面、旋转角度、安装槽位以及同步后的棋子位置。安装、旋转或翻面若造成立体交点冲突，动作会被拒绝且不修改草稿；平面棋子同步后若与现有装配冲突，编辑器会保留两种结构并提示重新装配，冲突消除前不能保存或开局。只有六块板全部安装且不存在棋子冲突时，才能保存立体布局并开局。

保存并启用立体布局后，游戏会直接以立体棋盘开局。棋子沿六面体连续表面移动：到达公共棱后可以进入任一相邻面，皇后的三步路线和象的菱形对角线也可以跨面延续，王沿六面体的真实棱在顶点间移动；王经过公共棱时，棱上的中间棋子不阻挡，只有目标顶点上的棋子参与占用和吃子判定。相邻面共享的公共棱交点和公共顶点只算一个物理位置，只能存在一枚棋子；从任一相邻面移动到被敌棋占据的共享位置都会按现有棋种规则触发吃子。公共棱和公共顶点上的棋子会在所有三角面之后统一绘制，因此旋转到不同视角时不会被相邻面遮住一部分。

立体棋盘发生吃子时不旋转整个棋体，升沉范围只由被吃棋子的物理位置决定，与攻击者的棋种、起点和移动路线无关。被吃棋子在公共顶点时，只让该顶点上的外层与内层棋子交换；在公共棱中间交点时，只让该物理棱（含两个端点）上的棋子交换，六个三角面保持不变；在三角面内部时，只让该三角面及其三条边界交换，并切换该面朝向，其他面保持不变。公共位置使用立体物理点、棱和面的几何关系识别，不依赖棋子保存的板面锚点，因此同一条公共棱从任一相邻面表示都会参与同一次升沉；没有吃子的移动不触发永久升沉。旧布局没有棋盘形态时按平面布局载入；没有棋子归属字段时，会按当前平面位置自动补齐。

编辑中的双面棋盘可以随时保存、载入、启用或删除。相同方案名允许同时存在一条平面记录和一条立体记录，覆盖其中一种结构不会覆盖另一种；立体记录的 `sourceFlatLayoutName` 必须与自身名称一致。旧版不同名棋子来源会在读取时复制为同名平面记录并保留原记录，避免迁移丢失。布局库提供默认平面布局，以及三组平面、立体同名且可直接游玩的测试预设。本地 Node 服务可用且项目目录可写时，布局保存到项目的 `layout-data/layouts.json`；静态部署或项目文件不可写时退回当前浏览器的 `localStorage`。“启用”覆盖当前形态结构并更新以后“重新开局”使用的起点，不会重置当前棋局或退出编辑；装配不完整、同名平面来源失效或缺少王时不会覆盖原存档。“保存并开局”则保存当前结构并立即开局。
