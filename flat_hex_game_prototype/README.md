# 平面六边形棋盘原型

本原型要验证的问题是：六个同规格三角形拼成的半径 4 六边形网格，能否用统一图结构表达王、皇后、象、兵的路线，并让玩家与自动演示共用同一套合法移动算法。

当前规则假设会显示在页面右侧。它们是用于讨论的原型定义，不代表最终规则已经锁定。

后吃象时双方换位且象降兵；象吃兵时兵消灭但象留在原位；兵吃兵或王后占据目标位置；王吃后时双方留在原位且后降象。符合条件的攻击方可以选择是否升级。

皇后每回合必须完整移动三步。自动演示采用迭代加深的分步博弈：依次展示一层直接收益、两层对手回应、三层己方反制，再执行最终动作。每层计算和最终落子前都会只高亮一个即将执行的候选操作，并用箭头和文字标明起点、目标及是否吃子。搜索使用 Alpha-Beta 剪枝，把升级与保持原级纳入评估，并通过局面指纹优先避开近期重复走法。连续模拟运行时可以随时暂停或继续；在立体棋盘中，视角会平滑跟随当前计算的棋子和最终落点，手动拖动仍可接管视角。

棋盘采用布局三的双面拼图。初始朝上面的六区依次使用 `5A / 6A / 3A / 4B / 1A / 2A`，下层统一按实体板垂直镜像关系保存，对应为 `3B / 6B / 5B / 2B / 1B / 4A`。两层各自保存棋盘配置和棋局状态；成功吃子会先结算当前层，然后不旋转棋盘，让当前棋盘与其全部棋子整体下沉，并让正下方对应的另一套棋盘与棋子整体上浮。换层过程保持六个空间槽位不动，例如同一槽位上的 `4A` 下沉时由其正下方的 `4B` 原位上浮，不会切换到镜像后的背面观看顺序。同一物理交点上下都有棋子时，两枚棋子随各自棋盘直接交换层级。

初始棋子位置按两张实体棋盘实拍图重新标定到六边形网格交点。照片一作为初始上层，照片二作为下层预览与首次换层后的初始布局；手写黑点是落子点，红色三角轮廓只用于辅助标出“象”，不作为额外棋子。

“预览背面”只切换显示内容，不修改当前层、回合、历史或棋子状态；预览期间棋子和算法控制均不可操作。吃子触发换层后，棋盘不旋转，原下层棋盘及其棋子整体上浮成为新的可操作层。

“自定义棋盘”会进入独立的空白双面编辑状态。点击任意交点可以设置或替换白/黑方的王、后、象、兵，也可以清空该点；A、B 两面分别编辑。每个交点最多一枚棋子，双面合计必须有且仅有一枚白王和一枚黑王，且王只能放在中心或六个外角。取消编辑不会改变原棋局，保存后从 A 面朝上、白方第 1 手开始。

自定义编辑包含“棋子摆放”和“板块拆装”两种工具。板块拆装模式下可直接选择六块三角板中的任意一块：旋转会让该板及板上的棋子顺时针转动120°，连续三次回到原方向；翻转会沿垂直轴镜像并交换该实体板的 A/B 面；交换会让它与随后点击的另一块板互换位置。三种操作都会同步维护整板另一面的垂直镜像槽位，方向随实体板一起交换。旧版按水平轴保存的布局会在读取时自动迁移，棋子身份及其在三角板内部的位置保持不变。

自定义棋盘可以选择保存为平面棋盘或双锥六面体立体棋盘。选择立体棋盘后会在当前页面的棋盘区域显示装配工作台，右侧布局编辑控件保持可见：六块实体三角板排列在待选区，中间显示六面体空骨架，并提供六个始终可点击的骨架槽位，避免立体投影中的面互相遮挡后无法准确安装。立体装配使用独立草稿，旋转、翻面或重装不会改写作为来源的同配置平面棋盘结构。选中待选板或骨架上的已安装板时，会预览该板当前朝上的面、旋转角度、安装槽位以及旋转后棋子的位置、阵营和身份。先选择三角板，可独立旋转120°或翻面，再点击中央空槽或对应槽位安装；点击已安装面或已占用槽位可以选中并拆下重装。每次安装、旋转或翻面都会同时检查当前外表面和翻面后的另一组表面，如果两个棋子会占用同一个立体交点，动作会被立即拒绝且不会修改装配草稿。只有六块板全部安装且不存在棋子冲突时，才能保存立体布局并开局。

保存并启用立体布局后，游戏会直接以立体棋盘开局。棋子沿六面体连续表面移动：到达公共棱后可以进入任一相邻面，皇后的三步路线和象的菱形对角线也可以跨面延续，王沿六面体的真实棱在顶点间移动；王经过公共棱时，棱上的中间棋子不阻挡，只有目标顶点上的棋子参与占用和吃子判定。相邻面共享的公共棱交点和公共顶点只算一个物理位置，只能存在一枚棋子；从任一相邻面移动到被敌棋占据的共享位置都会按现有棋种规则触发吃子。公共棱和公共顶点上的棋子会在所有三角面之后统一绘制，因此旋转到不同视角时不会被相邻面遮住一部分。

立体棋盘发生吃子时也不旋转整个棋体，当前外层的六个三角面配置与棋子整体下沉，内层对应的六个三角面配置与棋子整体上浮；公共棱和公共顶点与面内交点遵循同一换层规则。旧布局没有棋盘形态时按平面布局载入；没有棋子归属字段时，会按当前平面位置自动补齐。

编辑中的双面棋盘可以随时命名保存、载入、启用或删除。本地 Node 服务可用且项目目录可写时，布局保存到项目的 `layout-data/layouts.json` 文件；Vercel 等静态部署没有 `/api/layouts` 接口，或运行环境禁止写入项目文件时，会自动退回当前浏览器的 `localStorage`，不同设备和浏览器之间不会同步。布局库会自动提供四个不可覆盖、不可删除、不可载入编辑的内置可玩布局：原“默认布局”，以及“预设·平面快速吃子”“预设·平面双层对局”“预设·立体升沉测试”；已有存档会在读取时自动补齐这些预设并保留用户布局。布局草稿允许棋子尚未摆完，但 A、B 两面合计每方最多一枚王；“启用并开局”或“保存并开局”要求整副双面棋盘合计有且仅有一枚白王和一枚黑王。当前启用的布局会作为“重新开局”的固定起点。
