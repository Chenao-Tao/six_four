# 平面六边形棋盘原型

本原型要验证的问题是：六个同规格三角形拼成的半径 4 六边形网格，能否用统一图结构表达王、皇后、象、兵的路线，并让玩家与自动演示共用同一套合法移动算法。

当前规则假设会显示在页面右侧。它们是用于讨论的原型定义，不代表最终规则已经锁定。

后吃象时双方换位且象降兵；象吃兵时兵消灭但象留在原位；兵吃兵或王后占据目标位置；王吃后时双方留在原位且后降象。符合条件的攻击方可以选择是否升级。

皇后每回合必须完整移动三步。自动演示采用迭代加深的分步博弈：依次展示一层直接收益、两层对手回应、三层己方反制，再执行最终动作。搜索使用 Alpha-Beta 剪枝，把升级与保持原级纳入评估，并通过局面指纹优先避开近期重复走法。

棋盘采用布局三的双面拼图。初始朝上面的六区依次使用 `5A / 6A / 3A / 4B / 1A / 2A`，背面是实体板翻转后对应的 `2B / 1B / 4A / 3B / 6B / 5B`。两面各自保存棋局状态；成功吃子会先结算当前面，再将整个六边形板翻到另一面。

初始棋子位置按两张实体棋盘实拍图重新标定到六边形网格交点。照片一作为初始朝上面，照片二作为背面预览与实际翻面后的初始布局；手写黑点是落子点，红色三角轮廓只用于辅助标出“象”，不作为额外棋子。

“预览背面”只切换显示内容，不修改当前朝上面、回合、历史或棋子状态；预览期间棋子和算法控制均不可操作。只有吃子触发实际翻面后，原背面才成为新的可操作面。

“自定义棋盘”会进入独立的空白双面编辑状态。点击任意交点可以设置或替换白/黑方的王、后、象、兵，也可以清空该点；A、B 两面分别编辑。每个交点最多一枚棋子，双面合计必须有且仅有一枚白王和一枚黑王，且王只能放在中心或六个外角。取消编辑不会改变原棋局，保存后从 A 面朝上、白方第 1 手开始。

自定义编辑包含“棋子摆放”和“板块拆装”两种工具。板块拆装模式下可直接选择六块三角板中的任意一块：旋转会让该板及板上的棋子顺时针转动120°，连续三次回到原方向；翻转会交换该实体板的 A/B 面；交换会让它与随后点击的另一块板互换位置。三种操作都会同步维护整板另一面的镜像槽位，方向随实体板一起交换。

自定义棋盘可以选择保存为平面棋盘或双锥六面体立体棋盘。选择立体棋盘后会进入装配工作台：六块实体三角板排列在右侧待选区，中间显示六面体空骨架，左侧提供六个始终可点击的骨架槽位，避免立体投影中的面互相遮挡后无法准确安装。选中待选板或骨架上的已安装板时，左侧会预览该板当前朝上的面、旋转角度、安装槽位以及旋转后棋子的位置、阵营和身份。先选择三角板，可独立旋转120°或翻面，再点击中央空槽或左侧对应槽位安装；点击已安装面或已占用槽位可以选中并拆下重装。每次安装、旋转或翻面都会同时检查当前外表面和翻面后的另一组表面，如果两个棋子会占用同一个立体交点，动作会被立即拒绝且不会修改装配草稿。只有六块板全部安装且不存在棋子冲突时，才能保存立体布局并开局。

保存并启用立体布局后，游戏会直接以立体棋盘开局。棋子沿六面体连续表面移动：到达公共棱后可以进入任一相邻面，皇后的三步路线和象的菱形对角线也可以跨面延续，王沿六面体的真实棱在顶点间移动。相邻面共享的公共棱交点和公共顶点只算一个物理位置，只能存在一枚棋子；从任一相邻面移动到被敌棋占据的共享位置都会按现有棋种规则触发吃子。

立体棋盘发生面内吃子时只翻转吃子所在的三角面；在公共棱吃子时，则翻转攻击棋出发时所在的三角面。面内棋子随该面在外层与内层之间交换；公共棱由相邻两面共同约束，如果该棱的背面任意位置已有棋子，则整条棱上的外层棋子不下沉、内层棋子也不上浮。公共顶点由三条相交棱共同约束，只要其中任意一条棱的背面有棋子，该顶点就保持当前层级。没有背面支撑时，公共棱或顶点上的棋子会随发生吃子的面一起下沉。旧布局没有棋盘形态时按平面布局载入；没有棋子归属字段时，会按当前平面位置自动补齐。

编辑中的双面棋盘可以随时命名保存、载入、启用或删除。本地 Node 服务可用且项目目录可写时，布局保存到项目的 `layout-data/layouts.json` 文件；Vercel 等静态部署没有 `/api/layouts` 接口，或运行环境禁止写入项目文件时，会自动退回当前浏览器的 `localStorage`，不同设备和浏览器之间不会同步。首次运行会创建一个不可覆盖、不可删除、不可载入编辑的“默认布局”，保留既有参考图摆法；旧浏览器存档会自动迁移，不符合当前规则的旧存档会保留并显示错误。布局草稿允许棋子尚未摆完，但 A、B 两面合计每方最多一枚王；“启用并开局”或“保存并开局”要求整副双面棋盘合计有且仅有一枚白王和一枚黑王。当前启用的布局会作为“重新开局”的固定起点。

